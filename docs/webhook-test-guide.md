## 🔍 测试项目说明

### 1. 帐号状态检查
- **检查内容**: 用户的 `is_active` 字段
- **成功**: 帐号已启用
- **失败**: 帐号已停用，Webhook 将无法工作

### 2. Webhook Key 检查
- **检查内容**: 用户的 `webhook_key` 字段
- **成功**: Webhook Key 已设定且有效
- **失败**: Webhook Key 未设定或为空

### 3. Channel Secret 检查
- **检查内容**: 用户的 `line_channel_secret` 字段
- **成功**: Channel Secret 已设定
- **警告**: Channel Secret 未设定（签章验证将被跳过）

### 4. Webhook 请求测试
- **检查内容**: 实际发送 HTTP POST 请求到 Webhook endpoint
- **测试内容**:
  - URL 连通性
  - 签章验证（如果有 Channel Secret）
  - 响应状态码
  - 处理时间
- **成功**: HTTP 200 响应
- **失败**: HTTP 401（验证失败）或其他错误

### 5. Webhook 记录检查
- **检查内容**: 查询数据库中最近的测试记录
- **成功**: 找到最近 10 秒内的测试记录
- **信息**: 尚未找到测试请求记录

## 💡 使用建议

1. **定期测试**: 建议定期测试所有用户的 Webhook 配置
2. **配置变更后**: 修改 Webhook Key 或 Channel Secret 后立即测试
3. **问题排查**: 当 Webhook 无法正常工作时，使用此功能快速诊断
4. **查看记录**: 测试后可以在 Webhook 记录列表中找到测试请求（标记为"测试"）

## 🎨 视觉标识

- ✅ 绿色 = 成功
- ⚠️ 黄色 = 警告
- ❌ 红色 = 错误
- ℹ️ 蓝色 = 信息

## 📝 技术细节

测试过程会：
1. 构造标准的 LINE Webhook 请求格式
2. 使用用户的 Channel Secret 计算签章
3. 发送 HTTP POST 请求到本地 Webhook endpoint
4. 验证响应状态和内容
5. 检查数据库记录

测试请求的特征：
- `is_test_request = 1`（在数据库中标记）
- `events = []`（空事件数组）
- 带有正确的 `X-Line-Signature` header（如果有 Channel Secret）

## 🔗 相关功能

- **LINE 设定诊断** (在用户管理页面): 测试 Access Token 和 Bot 信息
- **Webhook 请求记录**: 查看所有 Webhook 请求的详细日志
- **用户管理**: 配置 Webhook Key 和 Channel Secret
